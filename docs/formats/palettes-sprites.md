# Palettes and sprites

Reader: `baba_formats::palette`, `baba_formats::sprites`,
`baba_formats::install::SpriteSet`.

## Palettes

- Files: `Data/Palettes/<name>.png` (global) and
  `Data/Worlds/<world>/Palettes/<name>.png` (per world).
- A palette is a small RGB PNG, 7 columns x 5 rows in every shipped file.
  Each pixel is one colour.
- Colours everywhere in the data (objects, level icons, overrides, the
  game's UI colour table) are palette **coordinates** `(x, y)`, written
  `{x, y}` in Lua and `x,y` in INI files. The RGB value depends on the
  palette of the current level, which is how one level can look completely
  different from another with the same objects.
- A level names its palette in `.ld` `[general] palette=` with
  `paletteroot=1` for the global directory and `0` for the world's
  directory. The reader falls back to the other directory if the file is
  missing there, and to `default.png` when the name is empty.
- Common coordinates used by the renderer side (not data, conventions of
  the game's UI colour table): the level background is `(0, 4)`, the area
  outside the level `(1, 0)`.

## Object sprites

- Files: `Data/Sprites/` (shared, "root") and `Data/Worlds/<world>/Sprites/`
  (world specific). An object's `sprite_in_root` (or `root` override) picks
  the directory; the reader also looks in the other one if the file is not
  found.
- Name scheme: `<sprite>_<variant>_<frame>.png`
  - `<sprite>` may contain underscores (`text_baba`, `button_move`).
  - `<variant>` is the number from the tiling scheme (direction, joined
    neighbours, animation step; see [objects.md](objects.md#tiling-sprite-variant-scheme)).
    Only the variants a sprite needs exist (a static object has only `0`).
  - `<frame>` is the wobble frame `1`, `2`, `3`; the game cycles them
    continuously for the hand-drawn "wobble".
- Size: 24x24 for almost all; some are wider/taller (26x24, 32x24, 30x30,
  48x24, 26x28, 32x32, ...). Larger sprites are centred on their cell.
- Pixels: white and greys on transparent. The sprite is drawn tinted by the
  object's palette colour (per-channel multiply), so white becomes exactly
  the palette colour and greys become darker shades of it. Some sprites have
  near-black detail pixels (`(8, 8, 8)`) that stay dark.
- Transparency: about half of the files are RGBA; the others are RGB with a
  PNG `tRNS` chunk marking pure black `(0, 0, 0)` as transparent. Decoders
  must honour `tRNS` (ours expands it to alpha). Three are palette PNGs.
- Files outside the scheme in sprite directories: `<name>_<frame>.png`
  single images, e.g. level-number icons named by `.ld` `[icons]` entries
  (`file=icon_island_1` means `icon_island_1.png`), a few stand-alone images
  (`icon.png`, `default_<frame>.png`). `SpriteDir::other_files` lists them,
  `SpriteDir::plain(stem)` finds one.
- `Data/Worlds/baba/Sprites_fi/` holds the on-screen control-hint sprites
  (`button_*`) with Finnish lettering, alternatives to those in `Sprites/`;
  levels do not reference the directory directly.

## Background images

`Data/Worlds/<world>/Images/<name>_<frame>.png` (frames 1..3), named by a
level's `[images]` section. They are already coloured (RGBA), cover the
playable area (792x432 = 33x18 cells of 24 px; `_full` variants are larger),
and are drawn below the grid at the first playable cell.

## Level previews and world icons

- `<stem>.png` next to each level: an RGB thumbnail (72x72 or 216x112),
  used by level selection screens; regenerated by the editor.
- `Data/Worlds/<world>/icon.png`: 48x48 world icon.

## Rendering a level (what the contact sheet does)

1. Resolve the object table (base slots + the level's `[tiles]`).
2. Load the level's palette.
3. Fill the playable area with the background colour and the border cells
   with the outside colour; draw `[images]` backgrounds.
4. For every non-empty, non-edge cell of every layer, look up the slot by
   tile id, choose the variant (tiling, facing, joined neighbours), take
   frame 1, tint with the slot's colour and draw, ordered by the slot's
   `layer` and then by grid order.
5. On maps, draw `[paths]` (their slot's sprite) and `[levels]` icons.

This is an approximation for checking the data (no rules, so text is never
shown "active"); the real presentation is specified separately.
